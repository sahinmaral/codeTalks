# codeTalks

🇹🇷 [Bu belgeyi Türkçe okuyun](README.tr.md)

**codeTalks** is a real-time chat application built for developers. This repository holds the mobile client — a React Native app built with Expo, talking to a custom-written .NET backend rather than a ready-made service like Firebase, with real-time messaging over SignalR.

The backend lives in [codeTalks.Backend](https://github.com/sahinmaral/codeTalks.Backend).

## Tech stack

| Concern | Choice |
|---|---|
| Runtime | React Native 0.76 on Expo SDK 52 (TypeScript) |
| Workflow | Expo CNG — `android/` and `ios/` are generated by `expo prebuild` and are not committed |
| Navigation | React Navigation — native stack + bottom tabs, with a custom tab bar |
| State | Redux Toolkit + redux-persist (AsyncStorage) |
| Networking | axios, with interceptors for auth, refresh-token rotation and `Accept-Language` |
| Real-time | `@microsoft/signalr` — chat hub and notification hub |
| Forms & validation | Formik + Yup, with translation-key-based messages |
| Localization | i18next / react-i18next — English + Turkish, device locale detection via `expo-localization` |
| Theming | Light / dark / system, with a `useThemedStyles` + `makeStyles` factory pattern |
| Push notifications | `expo-notifications` (Expo push service, FCM on Android) |
| UI | `@gorhom/bottom-sheet`, Reanimated, Lottie, Remix icons, Montserrat |
| Error tracking | Sentry (`@sentry/react-native`) |
| Testing | Jest (`jest-expo`) + React Native Testing Library |
| Builds | EAS Build (development / preview / production profiles) |

## Features

- **Auth** — sign up (two-step: credentials, then name details), login, logout, password change; JWT access tokens with rotating refresh tokens handled transparently
- **Channels** — create, join (open or request-to-join), leave, discover; per-channel roles (Owner/Moderator/User) with member management, join-request approval and bans
- **Messages** — real-time channel messaging over SignalR, paged history, relative timestamps
- **Profile** — profile info, avatar upload, online status, notification and per-channel mute settings
- **Notifications** — push notifications with per-channel and total unread counts, deep-linking into the right channel from a tapped notification
- **App shell** — connectivity check screen, theme and language switching, terms of service & privacy policy screens

## Architecture

```
src/
  components/   reusable UI (each with its own styles + tests)
  screens/      screen-level components, grouped per feature
  hooks/        SignalR connections, push notifications, theme, language, logout
  redux/        store, persisted reducers (app, activeChannel, theme, language)
  services/     axios instance + one API module per backend resource
  schemas/      Yup validation schemas
  localization/ i18n setup and en/tr locale files
  styles/       colors, typography, themed style helpers
  utils/        token manager, error mapping, image picker, Sentry, navigation ref
```

Two pieces are worth calling out:

- **`src/utils/tokenManager.ts`** is the single place a refresh token is ever spent. Concurrent callers — a burst of 401s from axios and a proactive refresh from the SignalR access-token factory — are de-duplicated into one exchange, so a rotating refresh token is never spent twice and the user is never logged out by a race. A network error or 5xx deliberately leaves the session intact; only an actual credential rejection ends it.
- **`useSignalRConnection` / `useNotificationHub`** own the chat and notification hub lifecycles, reconnecting with a fresh access token and staying in sync with the persisted auth state.

## Running locally

Requires Node 18+, Yarn, and a running [codeTalks.Backend](https://github.com/sahinmaral/codeTalks.Backend) instance.

```bash
yarn install
```

Create a `.env` file in the project root:

```env
EXPO_PUBLIC_API_BASE_URL=   # backend base URL, without /api (e.g. http://192.168.1.20:5050)
EXPO_PUBLIC_SENTRY_DSN=     # optional; Sentry stays disabled unless this is a real DSN URL
```

`EXPO_PUBLIC_API_BASE_URL` is used both for REST (`/api/...`) and for the SignalR hubs (`/hubs/chat`, `/hubs/notifications`), so on a physical device it must be your machine's LAN address rather than `localhost`.

This app uses native modules and a development build — Expo Go will not work. Build and run it on a device or simulator:

```bash
yarn ios       # expo run:ios
yarn android   # expo run:android
```

`android/` and `ios/` are generated, not committed. If native config changes (or the folders are missing), regenerate them with `npx expo prebuild --clean`. Android push notifications additionally need a `google-services.json` at the project root — it is gitignored, and its package name must match `com.sahinmaral.codetalks` in `app.json`.

Once a native build is installed, `yarn start` is enough for day-to-day work.

## Testing

```bash
yarn test         # 349 tests across 61 suites
yarn test:watch
```

The automated suite covers what can be tested without a device: validation schemas, reducers, hooks, API error mapping and component rendering/interaction via React Native Testing Library. Everything that genuinely needs hardware — push notifications, real-time delivery, native permissions — is covered by the manual checklist in [docs/qa-test-plan.md](docs/qa-test-plan.md), to be walked through before each release.

## Builds

EAS Build profiles live in `eas.json` (`development`, `preview`, `production`). Each profile carries its own `EXPO_PUBLIC_API_BASE_URL` and `EXPO_PUBLIC_SENTRY_DSN`; fill in the placeholders before building.

```bash
eas build --profile development --platform ios
eas build --profile production --platform android
```

## Notes

- Formatting is enforced with Prettier — `yarn format` / `yarn format:check`.
- `patch-package` runs on install; it currently patches `expo-localization` for a Swift exhaustiveness error under newer Xcode SDKs.
